# How I Build Software

I don't want to simply make features work.

I want to understand the system behind them.

```text id="nq1v5z"
Requirement
    ↓
Understand the problem
    ↓
Design the solution
    ↓
Model the data
    ↓
Build the API
    ↓
Build the UI
    ↓
Test & Debug
    ↓
Deploy
    ↓
Monitor & Improve
```

I care about:

**Readable Code**
Code should be understandable by the next developer — including future me.

**Reusable Systems**
Components, utilities, hooks, services, and patterns should be reusable when it makes sense.

**Type Safety**
Types should help prevent problems rather than simply describe them.

**Maintainability**
Software should be easy to modify long after the original feature was built.

**Architecture**
I want to understand not only *how* something works, but *why* it was designed that way.
